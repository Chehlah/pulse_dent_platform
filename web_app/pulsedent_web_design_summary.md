## 4. Header และสถานะอุปกรณ์ (Real-time Device Status)

ส่วนหัวใช้พื้นหลังไล่สี teal-blue และแสดงสถานะการเชื่อมต่อของบอร์ด ESP32 ตามข้อมูลจริงจาก Firebase:

องค์ประกอบที่มีอยู่:

- โลโก้ตัวอักษร `P` ในวงกลม
- ชื่อระบบ `PULSE DENT`
- ชื่อผลงานภาษาอังกฤษและภาษาไทย
- **จุดสถานะและข้อความสถานะอุปกรณ์ (`#headerDeviceStatus`):** เปลี่ยนสีและข้อความตามสถานะการส่งข้อมูลของ ESP32 แบบอัตโนมัติ:
  - **สีเขียว (`online`):** `ESP32 เชื่อมต่อสำเร็จ (XX.X °C)` — ได้รับข้อมูลใหม่จาก ESP32 ภายใน 6 วินาทีล่าสุด
  - **สีเหลือง (`stale` / `connecting`):** `กำลังเชื่อมต่อ Firebase...` หรือ `ESP32 สัญญาณไม่อัปเดต` — ไม่มีข้อมูลชุดใหม่เข้ามาเกิน 6 วินาที (แต่ไม่เกิน 15 วินาที)
  - **สีเทา (`offline`):** `ESP32 ออฟไลน์ (ข้อมูลไม่อัปเดต)` / `ESP32 ออฟไลน์ (ใช้ค่าจำลอง)` / `โหมดจำลอง (ปิดรับค่า ESP32)` — ข้อมูลไม่อัปเดตเกิน 15 วินาที หรือผู้ใช้ปิดสวิตช์รับค่าจาก ESP32
- แบตเตอรี่จำลองพร้อม icon และเปอร์เซ็นต์ (ค่าเริ่มต้น `67%` ปรับแก้ได้จากหน้า Settings)

## 5. Dashboard / Measurement และการรับค่าจาก ESP32

หน้า Dashboard เป็นหน้าหลักสำหรับตรวจวัด แบ่งเป็น 2 คอลัมน์บนหน้าจอใหญ่

### ฝั่งซ้าย: Dental Map

ใช้ภาพ `tooth_01.jpg` เป็นภาพพื้นหลัง แล้ววางปุ่มเลือกฟันทับด้วย CSS absolute positioning

รายละเอียดปัจจุบัน:

- ภาพฟันอยู่ในกรอบสีขาว มี label `UPPER` และ `LOWER` บนแผนผัง
- ฟันทุกซี่ใช้หมายเลข FDI ครบ 32 ซี่
- ปุ่มเลือกฟันมีขนาดและตำแหน่งกำหนดจากข้อมูลใน `toothMeta` พร้อม tooltip ระบุหมายเลข ชื่อไทย และชื่ออังกฤษ
- เลือกโหมดพื้นที่ตรวจได้ 2 แบบ: `อ้างอิง` (เริ่มต้นที่ฟัน `17`) และ `เป้าหมาย` (เริ่มต้นที่ฟัน `23`, โหมดเริ่มต้นเมื่อเปิดเว็บคือ **`เป้าหมาย`** เพื่อให้ค่าจาก ESP32 วิ่งเข้าฟันเป้าหมายได้ทันที)
- สัญลักษณ์สีบนแผนผังฟัน:
  - **สีเขียว:** พื้นที่อ้างอิง (`reference`)
  - **สีส้ม:** พื้นที่เป้าหมาย (`target`)
  - **วงแหวนสีน้ำเงินกระพริบ (`live-streaming`) + จุดสีน้ำเงินมุมขวาบน (`esp-assigned`):** ซี่ฟันที่กำลังรับค่าสดจาก ESP32 หรือถูกบันทึกค่าจาก ESP32 แล้ว
  - **สีเทา/จาง:** กลุ่มฟันที่ถูกปิดจาก Settings

### ฝั่งขวา: แผงสัญญาณ ESP32 (Live Sensor Card) และ Measurement Results

#### 5.1 การ์ดสัญญาณจากอุปกรณ์ ESP32 (`#liveSensorCard`)
แสดงสถานะและการควบคุมข้อมูลที่มาจาก Firebase Realtime Database (`/devices/<deviceId>/latest.json`):
- **สวิตช์ `เปิดรับค่าจาก ESP32`:** เปิด/ปิดการเชื่อมต่อกับ Firebase เพื่อสลับระหว่างโหมดรับค่าจริงกับโหมดจำลองล้วน
- **ป้ายสถานะ (`live-pill`):** แสดงสถานะ `รับค่าสดจาก ESP32` (สีเขียว), `รอข้อมูลใหม่จาก ESP32` (สีส้ม), `กำลังเชื่อมต่อ Firebase...` (สีส้ม) หรือ `ESP32 ออฟไลน์ (แสดงค่าล่าสุดที่ค้างอยู่)` (สีเทา)
- **กล่องค่าล่าสุดจากเซ็นเซอร์:** แสดงค่าอุณหภูมิ (`°C`) ทศนิยม 2 ตำแหน่ง, เวลาอัปเดตล่าสุดจาก `timestamp` ของเซิร์ฟเวอร์ Firebase และสถานะค่าชีพจร/ออกซิเจน (หาก ESP32 ส่งมาเฉพาะอุณหภูมิ ระบบจะคงค่าชีพจรและออกซิเจนจำลองของซี่ฟันนั้นไว้)
- **การส่งค่าเข้าซี่ฟัน (Tooth Routing):**
  - **โหมดอัตโนมัติ (`ส่งค่าสดเข้าฟันซี่ที่คลิกเลือกอัตโนมัติ (Real-time)`):** เมื่อเปิดไว้และ ESP32 ออนไลน์อยู่ ผู้ใช้คลิกเลือกฟันซี่ไหนบนแผนผัง (ไม่ว่าจะอยู่ในโหมดอ้างอิงหรือเป้าหมาย) ค่าอุณหภูมิจาก ESP32 จะไหลเข้าฟันซี่นั้นแบบ Real-time ทันที และเมื่อคลิกย้ายไปซี่อื่น ซี่เดิมจะถูกล็อกค่าไว้ (`✓ ค่าจาก ESP32`)
  - **ปุ่ม `นำค่านี้ไปใส่ฟัน XX`:** กดเพื่อนำค่าล่าสุดจากเซ็นเซอร์ไปใส่ในฟันซี่ที่เลือกด้วยตนเอง
  - **ปุ่ม `ล็อกค่าฟัน XX แล้วสลับไปเลือกเป้าหมาย/อ้างอิง`:** ช่วยให้วัดฟันอ้างอิงเสร็จแล้วกดล็อกค่าเพื่อสลับโหมดไปวัดฟันเป้าหมายต่อได้ในคลิกเดียว

#### 5.2 การ์ดผลการตรวจวัด 4 ใบ (`Measurement Grid`)
1. **พื้นที่อ้างอิง (`#referenceCard`):** แสดงข้อมูลฟันอ้างอิง พร้อมป้ายกำกับแหล่งที่มาของข้อมูล (`● ค่าสด ESP32`, `✓ ค่าจาก ESP32` หรือ `ค่าจำลอง`)
2. **พื้นที่เป้าหมาย (`#targetCard`):** แสดงข้อมูลฟันเป้าหมาย พร้อมป้ายกำกับแหล่งที่มาของข้อมูลเช่นเดียวกัน
3. **ค่าผลต่างและการประเมินความเสี่ยง (`#differenceCard`):** คำนวณผลต่างสัมบูรณ์ระหว่างฟันอ้างอิงกับฟันเป้าหมายแบบ Real-time
4. **สรุปผล (`#riskCard`):** แสดงระดับความเสี่ยง (`ปกติ`, `เฝ้าระวัง`, `เสี่ยงสูง`) พร้อมคำแนะนำ

ค่าที่แสดงในแต่ละฟัน:

| ค่า | หน่วย | คำที่ใช้บนเว็บ | แหล่งข้อมูลปัจจุบัน |
|---|---|---|---|
| `temp` | °C | อุณหภูมิ | รับค่าสดจาก ESP32 ผ่าน Firebase (หรือค่าจำลอง) |
| `pulse` | bpm | สัญญาณชีพจรของฟัน | รับจาก Firebase ถ้ามีฟิลด์ `pulse` (ถ้าไม่มีจะใช้ค่าจำลองของซี่ฟัน) |
| `oxygen` | % | ออกซิเจนในเนื้อเยื่อฟัน | รับจาก Firebase ถ้ามีฟิลด์ `oxygen` (ถ้าไม่มีจะใช้ค่าจำลองของซี่ฟัน) |

ปุ่มควบคุม:

- `รีเซ็ต`: คืนค่าฟันอ้างอิง `17` และฟันเป้าหมายตาม scenario ปัจจุบัน พร้อมล้างสถานะค่าที่ล็อกจาก ESP32
- `บันทึกผล`: บันทึกข้อมูลลงประวัติ แล้วพาไปแท็บประวัติ

## 5.3 กลไกการซิงก์ข้อมูลกับ Firebase และการตรวจสอบสถานะการเชื่อมต่อ

เว็บแอปเชื่อมต่อกับ Firebase Realtime Database ผ่าน REST Endpoint:
- **Database URL เริ่มต้น:** `https://pulsedent-02-default-rtdb.asia-southeast1.firebasedatabase.app`
- **Device ID เริ่มต้น:** `pulse-dent-01`
- **Path ที่อ่านข้อมูล:** `/devices/pulse-dent-01/latest.json`

**วิธีการรับข้อมูล (Hybrid Streaming + Polling):**
1. **Server-Sent Events (`EventSource`):** เปิดการเชื่อมต่อแบบ REST Streaming เพื่อรับ event `put` ทันทีที่ ESP32 อัปเดตข้อมูล
2. **HTTP Polling (`fetch`):** ดึงข้อมูลสำรองทุก ๆ `1000 ms` (ปรับได้ในหน้า Settings) เพื่อรองรับสภาพแวดล้อมที่ SSE ถูกตัด

**การตรวจสอบความสดของข้อมูลและสถานะการเชื่อมต่อ (`evaluateConnectionStatus`):**
- ระบบเปรียบเทียบ `raw.timestamp` (Unix epoch milliseconds ที่ Firebase Server ประทับไว้เมื่อ ESP32 ส่ง `PUT`) เพื่อแยกแยะว่าข้อมูลที่ได้เป็น **Packet ใหม่จาก ESP32** หรือเป็น **ข้อมูลเก่าที่ค้างอยู่ใน Firebase**
- หากเปิดเว็บขึ้นมาแล้วพบว่า `timestamp` ใน Firebase เก่าเกินกำหนด หรือระหว่างใช้งานไม่มี `timestamp` ใหม่เข้ามา ระบบจะเปลี่ยนสถานะตามเกณฑ์เวลาดังนี้:
  - **0 – 6 วินาที (`STALE_TIMEOUT_MS = 6000`):** สถานะ `online` (ESP32 เชื่อมต่อสำเร็จ และอนุญาตให้โหมด Auto-assign อัปเดตค่าเข้าซี่ฟัน)
  - **6 – 15 วินาที (`OFFLINE_TIMEOUT_MS = 15000`):** สถานะ `stale` (แจ้งเตือนว่า ESP32 สัญญาณไม่อัปเดต)
  - **มากกว่า 15 วินาที:** สถานะ `offline` (แจ้งว่า ESP32 ออฟไลน์ และหยุดการเขียนค่าค้างทับซี่ฟันอัตโนมัติ)

| State | ค่าเริ่มต้น |

| ฟันเป้าหมาย | `23` |
| scenario | `high` |
| การรับค่าสดจาก ESP32 | เปิด (`live.enabled = true`, `autoAssign = true`) |

## 8. Simulation Control

หน้า Simulation Control ใช้เลือกสถานการณ์จำลองก่อนสาธิต เมื่อเลือกแล้วระบบจะปรับค่าฟันเป้าหมายและกลับไปหน้า Dashboard

สถานการณ์ที่มีอยู่:

| Key | Label | ฟันเป้าหมาย | แนวคิด |
|---|---|---|---|
| `normal` | ฟันปกติ | 22 | ค่าใกล้เคียงพื้นที่อ้างอิง |
| `watch` | เฝ้าระวัง | 24 | อุณหภูมิและออกซิเจนต่างระดับกลาง |
| `high` | เสี่ยงสูง | 23 | ชีพจรหรือออกซิเจนลดลงชัดเจน |
| `necrosis` | แนวโน้มโพรงประสาทฟันตาย | 36 | ค่าตอบสนองต่ำมาก |
| `failed` | วัดไม่สำเร็จ | 34 | ลบค่าฟันเป้าหมายเพื่อแสดงกรณีอ่านค่าไม่ได้ |
| `noise` | สัญญาณรบกวน | 45 | ชีพจรแกว่งและออกซิเจนต่ำกว่าปกติ |

## 9. การคำนวณผลต่าง

เมื่อมีทั้งค่าพื้นที่อ้างอิงและพื้นที่เป้าหมาย ระบบคำนวณผลต่างด้วยค่าสัมบูรณ์

```js
diffTemp = Math.abs(reference.temp - target.temp);
diffPulse = Math.abs(reference.pulse - target.pulse);
diffOxygen = Math.abs(reference.oxygen - target.oxygen);
```

ผลต่างถูกนำไปแสดงในการ์ด `ค่าผลต่างและการประเมินความเสี่ยง`

---

## 10. เกณฑ์ประเมินความเสี่ยงปัจจุบัน

เกณฑ์เริ่มต้นอยู่ใน `defaultSettings.thresholds`

| เกณฑ์ | ค่าเริ่มต้น |
|---|---:|
| ผลต่างอุณหภูมิระดับเฝ้าระวัง | 2 °C |
| ผลต่างอุณหภูมิระดับเสี่ยงสูง | 5 °C |
| ผลต่างออกซิเจนระดับเฝ้าระวัง | 20 % |
| ผลต่างออกซิเจนระดับเสี่ยงสูง | 50 % |
| ชีพจรต่ำผิดปกติ | 1 bpm |

ตรรกะการประเมิน:

| เงื่อนไข | ระดับ | ข้อความ |
|---|---|---|
| `diffTemp > tempHigh` หรือ `target.pulse < pulseLow` หรือ `diffOxygen > oxygenHigh` | เสี่ยงสูง | มีแนวโน้มภาวะโพรงประสาทฟันผิดปกติ ควรตรวจยืนยันโดยทันตแพทย์ |
| `diffTemp >= tempWarn` หรือ `diffOxygen >= oxygenWarn` | เฝ้าระวัง | พบความแตกต่างจากพื้นที่อ้างอิง ควรตรวจซ้ำ |
| ไม่เข้าเงื่อนไขข้างต้น | ปกติ | ไม่พบความผิดปกติจากค่าที่ตรวจวัด |

ทุกผลลัพธ์มี note กำกับว่าเป็นการประเมินเบื้องต้นจากระบบจำลอง

## 12. Settings

หน้า Settings แบ่งเป็น 4 กลุ่ม

### Display

เปิด/ปิดข้อมูลที่แสดงหน้าหลัก:

- อุณหภูมิ
- สัญญาณชีพจรของฟัน
- ออกซิเจนในเนื้อเยื่อฟัน
- หมายเลขฟัน FDI
- ชื่อชนิดฟัน
- ตำแหน่งขากรรไกร
- แบตเตอรี่อุปกรณ์จำลอง 0-100%

### Tooth Groups

เปิด/ปิดกลุ่มฟันที่กดเลือกได้ตามชนิดฟัน เช่น central incisors, canines, molars เป็นต้น

เมื่อปิดกลุ่มฟัน:

- ปุ่มฟันกลุ่มนั้นจะจางลง
- กดเลือกไม่ได้
- มีสถานะ `aria-disabled="true"`

### Threshold

แก้เกณฑ์ประเมินความเสี่ยงได้จาก input ตัวเลข

- ผลต่างอุณหภูมิระดับเฝ้าระวัง
- ผลต่างอุณหภูมิระดับเสี่ยงสูง
- ผลต่างออกซิเจนระดับเฝ้าระวัง
- ผลต่างออกซิเจนระดับเสี่ยงสูง
- ชีพจรต่ำผิดปกติ

มีปุ่ม `คืนค่าตั้งต้น` เพื่อกลับไปใช้ `defaultSettings`

### ESP32 & Firebase Connection

ตั้งค่าการเชื่อมต่อกับ Firebase Realtime Database ได้จากหน้าเว็บโดยไม่ต้องแก้โค้ด:

- **Firebase Database URL:** ค่าเริ่มต้น `https://pulsedent-02-default-rtdb.asia-southeast1.firebasedatabase.app`
- **Device ID (ESP32):** ค่าเริ่มต้น `pulse-dent-01`
- **รอบดึงข้อมูล (ms):** ค่าเริ่มต้น `1000` ms (ตั้งแต่ 500 – 10,000 ms)
- ปุ่ม **`บันทึกและเชื่อมต่อใหม่`:** บันทึกค่าลง `localStorage` และเริ่มซิงก์กับ Firebase ใหม่ทันที

การตั้งค่าทั้งหมดเก็บใน `localStorage` key `pulsedent-settings`

## 17. ข้อจำกัดปัจจุบัน

1. ปัจจุบันบอร์ด ESP32 ส่งค่าอุณหภูมิ (`temperature`) ผ่าน Firebase แบบ Real-time แล้ว ส่วนค่าชีพจร (`pulse`) และออกซิเจน (`oxygen`) หากยังไม่ได้ส่งมาจาก ESP32 ระบบจะใช้ค่าจำลองของซี่ฟันนั้นประกอบการประเมินผล
2. ประวัติการตรวจและการตั้งค่าของผู้ใช้เก็บใน `localStorage` ของ browser เท่านั้น (ยังไม่บันทึกประวัติย้อนหลังกลับขึ้น Firebase)
3. ยังไม่มีระบบผู้ป่วยจริงหรือการเลือกชื่อผู้ป่วย (ยังใช้ชื่อ `Demo Patient`)
4. ยังไม่มี export PDF/CSV
5. แผนผังฟันเป็น JPG + overlay button ถ้าเปลี่ยนภาพต้องปรับตำแหน่งใหม่
6. ยังไม่มีระบบ authentication สำหรับจำกัดสิทธิ์การเข้าถึงบนหน้าเว็บ
7. ไม่มีการ validate ทางคลินิก เพราะเกณฑ์ทั้งหมดเป็นเกณฑ์เบื้องต้นเพื่อการสาธิต

## 18. แนวทางพัฒนาต่อ

ลำดับที่เหมาะสมสำหรับพัฒนาต่อ:

1. เพิ่มการส่งค่าเซ็นเซอร์ชีพจร (`pulse`) และออกซิเจน (`oxygen`) หรือค่าแบตเตอรี่จริงจากบอร์ด ESP32 ขึ้น Firebase ให้ครบทุกพารามิเตอร์
2. บันทึกประวัติการตรวจ (`history`) ขึ้น Firebase Realtime Database เพื่อให้ดูประวัติข้ามอุปกรณ์ได้
3. เพิ่มฟอร์มเลือก/กรอกผู้รับการตรวจแทน `Demo Patient`
4. เพิ่ม export ผลเป็น PDF/CSV สำหรับใช้ประกอบการนำเสนอ
5. เพิ่มกราฟเปรียบเทียบค่าระหว่าง reference/target และแนวโน้มอุณหภูมิแบบ Real-time
6. เปลี่ยน dental map จาก JPG overlay เป็น SVG clickable map เพื่อความแม่นยำ
7. เพิ่มระบบ login แยกบทบาททันตแพทย์/ผู้ดูแล/ผู้สาธิต
8. เพิ่มชุดข้อความภาษาอังกฤษเพื่อใช้พรีเซนต์แบบ bilingual

## 19. สรุปสถานะปัจจุบัน

เว็บ PulseDent Platform ในโฟลเดอร์ `web_app` ตอนนี้รองรับ **การรับค่าอุณหภูมิแบบ Real-time จากบอร์ด ESP32 ผ่าน Firebase Realtime Database** ร่วมกับระบบจำลองได้อย่างสมบูรณ์:
- แสดงสถานะการเชื่อมต่อของ ESP32 (`เชื่อมต่อสำเร็จ`, `สัญญาณไม่อัปเดต`, `ออฟไลน์`) ตามอายุของ `timestamp` จริงใน Firebase
- สามารถคลิกเลือกฟันซี่ใดก็ได้บนแผนผัง (ทั้งฟันอ้างอิงและฟันเป้าหมาย) เพื่อนำค่าจาก ESP32 ไปใส่ในซี่ฟันนั้นแบบอัตโนมัติ (Real-time) หรือกดล็อกค่าทีละซี่เพื่อเปรียบเทียบผลต่าง
- คำนวณผลต่าง ประเมินความเสี่ยง บันทึกประวัติ และปรับตั้งค่า Firebase URL / Device ID ได้จากหน้าเว็บโดยตรง
