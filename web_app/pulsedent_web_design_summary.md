## 1. ภาพรวมผลงาน

**ชื่อภาษาไทย:**  
พัลส์เดนต์: อุปกรณ์อัจฉริยะสำหรับประเมินภาวะโพรงประสาทฟันตายร่วมกับแพลตฟอร์มดิจิทัล

**ชื่อภาษาอังกฤษ:**  
PulseDent: Smart Dental Pulp Vitality Assessment Device and Platform

**ชื่อที่ใช้บนเว็บ:**  
PulseDent Platform / PULSE DENT

**บทบาทของเว็บ:**  
เว็บแอปสำหรับนำเสนอและประเมินภาวะโพรงประสาทฟันเบื้องต้น โดยเชื่อมต่อกับอุปกรณ์ **ESP32 ผ่าน Firebase Realtime Database แบบสองทิศทาง (Two-Way Control & Real-time Sync)** สามารถสั่ง **เริ่มการวัด (Start) / หยุดการวัด (Stop)** ได้ทั้งจากปุ่มบนหน้าเว็บและปุ่มกดจริงบนบอร์ด ESP32 (GPIO 18) พร้อมรับค่าอุณหภูมิแบบ Real-time เพื่อนำไปใส่ในซี่ฟันที่เลือกบนแผนผังได้ทันที (ทั้งฝั่งฟันอ้างอิงและฟันเป้าหมาย) และมีโหมดข้อมูลจำลอง (Simulation Control) สำหรับสาธิตสถานการณ์ความเสี่ยงต่าง ๆ ได้ครบกระบวนการ

**คำเตือนสำคัญ:**  
ผลลัพธ์บนเว็บเป็นการประเมินเบื้องต้น ควรตรวจยืนยันโดยทันตแพทย์ และไม่ควรใช้ถ้อยคำที่ฟันธงว่าเป็นการวินิจฉัยโรคจริง

## 4. Header และสถานะอุปกรณ์ (Real-time Device Status)

ส่วนหัวใช้พื้นหลังไล่สี teal-blue และแสดงสถานะการเชื่อมต่อของบอร์ด ESP32 ตามข้อมูลจริงจาก Firebase:

องค์ประกอบที่มีอยู่:

- โลโก้ตัวอักษร `P` ในวงกลม
- ชื่อระบบ `PULSE DENT`
- ชื่อผลงานภาษาอังกฤษและภาษาไทย
- **จุดสถานะและข้อความสถานะอุปกรณ์ (`#headerDeviceStatus`):** เปลี่ยนสีและข้อความตามสถานะการเชื่อมต่อและการวัดของ ESP32 แบบอัตโนมัติ:
  - **สีเขียว (`online`):**
    - ขณะกำลังวัด (`measuring = true`): `ESP32: Online · Measuring (XX.X °C)`
    - ขณะพักรอ (`measuring = false` / Standby): `ESP32: Online · Standby (--.-- °C)`
    *(ได้รับ Heartbeat `state/lastSeen` หรือข้อมูลใหม่ `latest/timestamp` จาก ESP32 ภายใน 6 วินาทีล่าสุด)*
  - **สีเหลือง (`stale` / `connecting`):** `กำลังเชื่อมต่อ Firebase...` หรือ `ESP32 สัญญาณไม่อัปเดต` — ไม่มี Heartbeat หรือข้อมูลชุดใหม่เข้ามาเกิน 6 วินาที (แต่ไม่เกิน 12 วินาที)
  - **สีเทา (`offline`):** `ESP32: Offline · ไม่พร้อมวัด` หรือ `โหมดจำลอง (ปิดรับค่า ESP32)` — ข้อมูล/Heartbeat ไม่อัปเดตเกิน 12 วินาที หรือผู้ใช้ปิดสวิตช์รับค่าจาก ESP32
- แบตเตอรี่อุปกรณ์พร้อม icon และเปอร์เซ็นต์ (ค่าเริ่มต้น `67%` ปรับแก้ได้จากหน้า Settings)

### ฝั่งขวา: แผงสัญญาณ ESP32 (Live Sensor Card) และ Measurement Results

#### 5.1 การ์ดสัญญาณจากอุปกรณ์ ESP32 (`#liveSensorCard`)
รองรับการเชื่อมต่อและควบคุมแบบสองทิศทาง (Two-Way Control) กับบอร์ด **ESP32 สูงสุด 2 โมดูลพร้อมกัน** ผ่าน Firebase Realtime Database (`/devices/pulse-dent-01.json` สำหรับอุณหภูมิ และ `/devices/pulse-dent-02.json` สำหรับชีพจร):
- **ป้ายสรุปเซ็นเซอร์ที่เชื่อมต่อ (`.live-summary-pill`):** แสดงชัดเจนว่ากำลังเชื่อมต่อเซ็นเซอร์แบบใดอยู่ เช่น `เชื่อมต่อ 1 ชนิด: อุณหภูมิ`, `เชื่อมต่อ 1 ชนิด: สัญญาณชีพจร`, `เชื่อมต่อ 2 ชนิด: อุณหภูมิ + ชีพจร` หรือ `ยังไม่พบอุปกรณ์ออนไลน์`
- **สวิตช์ `เปิดรับค่าจาก ESP32`:** เปิด/ปิดการเชื่อมต่อกับ Firebase ทั้งหมดเพื่อสลับระหว่างโหมดรับค่าจริงกับโหมดจำลองล้วน
- **แถบควบคุมพร้อมกัน 2 โมดูล (`.live-batch-bar`):** แสดงปุ่ม **`เริ่มวัดทั้งหมด`** และ **`หยุดทั้งหมด`** อัตโนมัติเมื่อทั้ง 2 โมดูลออนไลน์พร้อมกัน
- **การ์ดย่อยแยกตามโมดูล (`.dual-device-grid` — อุณหภูมิ Mode 1 และ สัญญาณชีพจร Mode 2):**
  - แสดงป้ายสถานะ `Connection` (`Online`, `สัญญาณไม่อัปเดต`, `กำลังเชื่อมต่อ...`, `Offline`) และสถานะการวัด (`Measuring`, `Standby`, `กำลังเริ่ม...`, `กำลังหยุด...`, `ไม่พร้อมวัด`) แยกกันอิสระ
  - แสดงค่าสดของแต่ละโมดูล (`XX.XX °C` / `XX bpm`) เมื่อกำลังวัด และซ่อนเป็น `--.-- °C` / `-- bpm` เมื่อ Standby หรือ Offline
  - มีปุ่ม **`เริ่มการวัด` / `หยุดการวัด`** แยกแต่ละโมดูล โดยส่ง `HTTP PUT` ไปยัง `/devices/<deviceId>/control/command.json` พร้อม Timeout 8 วินาที (`COMMAND_TIMEOUT_MS = 8000`) และซิงก์กับปุ่มกดจริงบนบอร์ด ESP32 (GPIO 18) ของแต่ละตัว
- **การส่งค่าเข้าซี่ฟัน (Tooth Routing):**
  - รองรับการรับค่าทั้ง **1 ชนิด** (เฉพาะอุณหภูมิ หรือ เฉพาะชีพจร) และ **2 ชนิดพร้อมกัน** (อุณหภูมิ + ชีพจร) โดยค่าที่ไม่ได้รับจาก ESP32 จะคงค่าจำลองของซี่ฟันนั้นไว้
  - **โหมดอัตโนมัติ (`autoAssign`):** ค่าเริ่มต้นคือ **ปิด (`false`)** หากติ๊กเปิดไว้และมีอย่างน้อย 1 โมดูลที่ `Online` + `Measuring` ค่าจะไหลเข้าซี่ฟันที่เลือกแบบ Real-time ทันที
  - **ปุ่ม `นำค่านี้ไปใส่ฟัน XX` และ `ล็อกค่าฟัน XX แล้วสลับไปเลือก...`:** เปิดให้กดเมื่อมีอย่างน้อย 1 โมดูลกำลังวัดอยู่ และอัปเดตป้ายแหล่งที่มาบนการ์ดฟันเป็น `✓ ESP32 (Temp)`, `✓ ESP32 (Pulse)` หรือ `✓ ESP32 (Temp+Pulse)`

#### 5.2 การ์ดผลการตรวจวัด 4 ใบ (`Measurement Grid`)
1. **พื้นที่อ้างอิง (`#referenceCard`):** แสดงข้อมูลฟันอ้างอิง พร้อมป้ายกำกับแหล่งที่มาของข้อมูล (`● ค่าสด ESP32`, `✓ ค่าจาก ESP32` หรือ `ค่าจำลอง`)
2. **พื้นที่เป้าหมาย (`#targetCard`):** แสดงข้อมูลฟันเป้าหมาย พร้อมป้ายกำกับแหล่งที่มาของข้อมูลเช่นเดียวกัน
3. **ค่าผลต่างและการประเมินความเสี่ยง (`#differenceCard`):** คำนวณผลต่างสัมบูรณ์ระหว่างฟันอ้างอิงกับฟันเป้าหมายแบบ Real-time
4. **สรุปผล (`#riskCard`):** แสดงระดับความเสี่ยง (`ปกติ`, `เฝ้าระวัง`, `เสี่ยงสูง`) พร้อมคำแนะนำ

ค่าที่แสดงในแต่ละฟัน:

| ค่า | หน่วย | คำที่ใช้บนเว็บ | แหล่งข้อมูลปัจจุบัน |
|---|---|---|---|
| `temp` | °C | อุณหภูมิ | รับค่าสดจาก ESP32 ผ่าน Firebase (หรือค่าจำลอง) |
| `pulse` | bpm | สัญญาณชีพจรของฟัน | รับจาก Firebase ถ้ามีฟิลด์ `pulse` (ถ้าไม่มีจะใช้ค่าจำลองของซี่ฟัน) |
| `oxygen` | % | ออกซิเจนในเนื้อเยื่อฟัน | รับจาก Firebase ถ้ามีฟิลด์ `oxygen` (ถ้าไม่มีจะใช้ค่าจำลองของซี่ฟัน) |

ปุ่มควบคุม:

- `รีเซ็ต`: คืนค่าฟันอ้างอิง `17` และฟันเป้าหมายตาม scenario ปัจจุบัน พร้อมล้างสถานะค่าที่ล็อกจาก ESP32
- `บันทึกผล`: บันทึกข้อมูลลงประวัติ แล้วพาไปแท็บประวัติ

## 5.3 กลไกการซิงก์ข้อมูลกับ Firebase และการตรวจสอบสถานะการเชื่อมต่อ

เว็บแอปเชื่อมต่อกับ Firebase Realtime Database ผ่าน REST Endpoint:
- **Database URL เริ่มต้น:** `https://pulsedent-02-default-rtdb.asia-southeast1.firebasedatabase.app`
- **Device ID เริ่มต้น:** `pulse-dent-01`
- **Path ที่อ่านข้อมูลทั้งหมดของอุปกรณ์:** `/devices/pulse-dent-01.json` (ประกอบด้วยโหนด `control`, `state`, และ `latest`)
- **Path ที่ส่งคำสั่งควบคุมการวัด (Start/Stop):** `/devices/pulse-dent-01/control/command.json`

**วิธีการรับและส่งข้อมูล (Hybrid Streaming + Polling + REST PUT):**
1. **Server-Sent Events (`EventSource`):** เปิดการเชื่อมต่อแบบ REST Streaming ไปที่ `/devices/<deviceId>.json` เพื่อรับ event `put` และ `patch` ทันทีเมื่อ `state` (`measuring`, `lastSeen`) หรือ `latest` (`temperature`, `timestamp`) มีการเปลี่ยนแปลง
2. **HTTP Polling (`fetch`):** ดึงข้อมูลสำรองจาก `/devices/<deviceId>.json` ทุก ๆ `1000 ms` (ปรับได้ในหน้า Settings) เพื่อรองรับสภาพแวดล้อมที่ SSE ถูกตัด
3. **HTTP PUT (`sendToggleMeasurementCommand`):** เขียนคำสั่ง `"start"` หรือ `"stop"` ไปยัง `/devices/<deviceId>/control/command.json` พร้อมระบบ Timeout 8 วินาที (`COMMAND_TIMEOUT_MS = 8000`) รอรับการยืนยันจาก `state/measuring`

**การตรวจสอบความสดของข้อมูลและสถานะการเชื่อมต่อ (`evaluateConnectionStatus`):**
- ระบบตรวจความสดของสัญญาณจากเวลาล่าสุดระหว่าง **Heartbeat (`state/lastSeen` ที่ ESP32 ส่งทุก 3 วินาทีแม้ในโหมด Standby)** และ **ข้อมูลอุณหภูมิ (`latest/timestamp` ที่ ESP32 ส่งทุก 1 วินาทีขณะ Measuring)**
- ทำให้เว็บแอปทราบว่า ESP32 ยังออนไลน์อยู่ในโหมด Standby แม้ไม่ได้ส่งค่าอุณหภูมิใหม่ และเปลี่ยนสถานะตามเกณฑ์เวลาดังนี้:
  - **0 – 6 วินาที (`STALE_TIMEOUT_MS = 6000`):** สถานะ `online` (ESP32 ออนไลน์ พร้อมรับคำสั่ง Start/Stop และอนุญาตให้อัปเดตค่าเข้าซี่ฟันขณะ `measuring = true`)
  - **6 – 12 วินาที (`OFFLINE_TIMEOUT_MS = 12000`):** สถานะ `stale` (แจ้งเตือนว่า ESP32 สัญญาณไม่อัปเดต)
  - **มากกว่า 12 วินาที:** สถานะ `offline` (แจ้งว่า `ESP32: Offline · ไม่พร้อมวัด`, ปิดปุ่มเริ่มการวัด และหยุดการเขียนค่าทับซี่ฟันอัตโนมัติ)

## 6. ระบบหมายเลขฟันและข้อมูลฟัน

เว็บใช้ระบบหมายเลขฟันแบบ FDI ครบทุก quadrant

| กลุ่ม | หมายเลข |
|---|---|
| ฟันบนขวา | 18, 17, 16, 15, 14, 13, 12, 11 |
| ฟันบนซ้าย | 21, 22, 23, 24, 25, 26, 27, 28 |
| ฟันล่างซ้าย | 38, 37, 36, 35, 34, 33, 32, 31 |
| ฟันล่างขวา | 41, 42, 43, 44, 45, 46, 47, 48 |

กลุ่มชนิดฟันที่รองรับ:

- ฟันตัดกลาง / central incisors
- ฟันตัดข้าง / lateral incisors
- ฟันเขี้ยว / canines / cuspides
- ฟันกรามน้อยซี่ที่หนึ่ง / first premolars
- ฟันกรามน้อยซี่ที่สอง / second premolars
- ฟันกรามซี่ที่หนึ่ง / first molars
- ฟันกรามซี่ที่สอง / second molars
- ฟันกรามซี่ที่สาม / third molars

ตำแหน่งปุ่มฟันเก็บใน `toothMeta` เป็นเปอร์เซ็นต์ของพื้นที่ภาพ เพื่อให้ responsive ตามขนาดรูปได้

## 7. ข้อมูลจำลองเริ่มต้น

ข้อมูลค่าพื้นฐานของฟันทุกซี่เก็บใน `baseToothData` ภายใน `script.js`

ตัวอย่างค่าเริ่มต้น:

```js
"17": { temp: 36.3, pulse: 78, oxygen: 85 }
"23": { temp: 28.0, pulse: 0, oxygen: 0 }
"36": { temp: 36.5, pulse: 79, oxygen: 87 }
```

สถานะเริ่มต้นของเว็บ:

| State | ค่าเริ่มต้น |
|---|---|
| โหมดเลือกฟัน | `target` (เป้าหมาย) |
| ฟันอ้างอิง | `17` |
| ฟันเป้าหมาย | `23` |
| scenario | `high` |
| การรับค่าสดจาก ESP32 | เปิดรับค่า (`live.enabled = true`), ปิดส่งค่าเข้าซี่ฟันอัตโนมัติเป็นค่าเริ่มต้น (`autoAssign = false`), เริ่มต้นในโหมด `measuring = false` (Standby) |
| ผลบน badge | `เสี่ยงสูง` (และอัปเดตตามค่าจริงเมื่อรับค่าจาก ESP32) |
| ประวัติเริ่มต้น | มีรายการ demo 1 รายการ |

## 8. Simulation Control

## 9. การคำนวณผลต่าง

เมื่อมีทั้งค่าพื้นที่อ้างอิงและพื้นที่เป้าหมาย ระบบคำนวณผลต่างด้วยค่าสัมบูรณ์

```js
diffTemp = Math.abs(reference.temp - target.temp);
diffPulse = Math.abs(reference.pulse - target.pulse);
diffOxygen = Math.abs(reference.oxygen - target.oxygen);
```

ผลต่างถูกนำไปแสดงในการ์ด `ค่าผลต่างและการประเมินความเสี่ยง`

## 10. เกณฑ์ประเมินความเสี่ยงปัจจุบัน

เกณฑ์เริ่มต้นอยู่ใน `defaultSettings.thresholds`

| เกณฑ์ | ค่าเริ่มต้น |
|---|---:|
| ผลต่างอุณหภูมิระดับเฝ้าระวัง | 2 °C |
| ผลต่างอุณหภูมิระดับเสี่ยงสูง | 5 °C |
| ผลต่างออกซิเจนระดับเฝ้าระวัง | 20 % |
| ผลต่างออกซิเจนระดับเสี่ยงสูง | 50 % |
| ชีพจรต่ำผิดปกติ | 1 bpm |

ตรรกะการประเมิน:

| เงื่อนไข | ระดับ | ข้อความ |
|---|---|---|
| `diffTemp > tempHigh` หรือ `target.pulse < pulseLow` หรือ `diffOxygen > oxygenHigh` | เสี่ยงสูง | มีแนวโน้มภาวะโพรงประสาทฟันผิดปกติ ควรตรวจยืนยันโดยทันตแพทย์ |
| `diffTemp >= tempWarn` หรือ `diffOxygen >= oxygenWarn` | เฝ้าระวัง | พบความแตกต่างจากพื้นที่อ้างอิง ควรตรวจซ้ำ |
| ไม่เข้าเงื่อนไขข้างต้น | ปกติ | ไม่พบความผิดปกติจากค่าที่ตรวจวัด |

ทุกผลลัพธ์มี note กำกับว่า: `ผลลัพธ์นี้เป็นการประเมินเบื้องต้น ควรตรวจยืนยันโดยทันตแพทย์`

## 12. Settings

หน้า Settings แบ่งเป็น 4 กลุ่ม

### Display

เปิด/ปิดข้อมูลที่แสดงหน้าหลัก:

- อุณหภูมิ
- สัญญาณชีพจรของฟัน
- ออกซิเจนในเนื้อเยื่อฟัน
- หมายเลขฟัน FDI
- ชื่อชนิดฟัน
- ตำแหน่งขากรรไกร
- แบตเตอรี่อุปกรณ์ 0-100%

### Tooth Groups

เปิด/ปิดกลุ่มฟันที่กดเลือกได้ตามชนิดฟัน เช่น central incisors, canines, molars เป็นต้น

เมื่อปิดกลุ่มฟัน:

- ปุ่มฟันกลุ่มนั้นจะจางลง
- กดเลือกไม่ได้
- มีสถานะ `aria-disabled="true"`

### Threshold

แก้เกณฑ์ประเมินความเสี่ยงได้จาก input ตัวเลข

- ผลต่างอุณหภูมิระดับเฝ้าระวัง
- ผลต่างอุณหภูมิระดับเสี่ยงสูง
- ผลต่างออกซิเจนระดับเฝ้าระวัง
- ผลต่างออกซิเจนระดับเสี่ยงสูง
- ชีพจรต่ำผิดปกติ

มีปุ่ม `คืนค่าตั้งต้น` เพื่อกลับไปใช้ `defaultSettings`

### ESP32 & Firebase Connection

ตั้งค่าการเชื่อมต่อกับ Firebase Realtime Database ได้จากหน้าเว็บโดยไม่ต้องแก้โค้ด:

- **Firebase Database URL:** ค่าเริ่มต้น `https://pulsedent-02-default-rtdb.asia-southeast1.firebasedatabase.app`
- **Device ID — อุณหภูมิ (Mode 1):** ค่าเริ่มต้น `pulse-dent-01`
- **Device ID — ชีพจร (Mode 2):** ค่าเริ่มต้น `pulse-dent-02`
- **รอบดึงข้อมูล (ms):** ค่าเริ่มต้น `1000` ms (ตั้งแต่ 500 – 10,000 ms)
- ปุ่ม **`บันทึกและเชื่อมต่อใหม่`:** บันทึกค่าลง `localStorage` และเริ่มซิงก์กับ Firebase ใหม่ทันทีทั้ง 2 โมดูล

การตั้งค่าทั้งหมดเก็บใน `localStorage` key `pulsedent-settings`

## 17. ข้อจำกัดปัจจุบัน

1. ปัจจุบันบอร์ด ESP32 ส่งค่าอุณหภูมิ (`temperature`) ผ่าน Firebase แบบ Real-time แล้ว ส่วนค่าชีพจร (`pulse`) และออกซิเจน (`oxygen`) หากยังไม่ได้ส่งมาจาก ESP32 ระบบจะใช้ค่าจำลองของซี่ฟันนั้นประกอบการประเมินผล
2. ประวัติการตรวจและการตั้งค่าของผู้ใช้เก็บใน `localStorage` ของ browser เท่านั้น (ยังไม่บันทึกประวัติย้อนหลังกลับขึ้น Firebase)
3. ยังไม่มีระบบผู้ป่วยจริงหรือการเลือกชื่อผู้ป่วย (ยังใช้ชื่อ `Demo Patient`)
4. ยังไม่มี export PDF/CSV
5. แผนผังฟันเป็น JPG + overlay button ถ้าเปลี่ยนภาพต้องปรับตำแหน่งใหม่
6. ยังไม่มีระบบ authentication สำหรับจำกัดสิทธิ์การเข้าถึงบนหน้าเว็บ
7. ไม่มีการ validate ทางคลินิก เพราะเกณฑ์ทั้งหมดเป็นเกณฑ์เบื้องต้นเพื่อการสาธิต

## 18. แนวทางพัฒนาต่อ

ลำดับที่เหมาะสมสำหรับพัฒนาต่อ:

1. เพิ่มการส่งค่าเซ็นเซอร์ชีพจร (`pulse`) และออกซิเจน (`oxygen`) หรือค่าแบตเตอรี่จริงจากบอร์ด ESP32 ขึ้น Firebase ให้ครบทุกพารามิเตอร์
2. บันทึกประวัติการตรวจ (`history`) ขึ้น Firebase Realtime Database เพื่อให้ดูประวัติข้ามอุปกรณ์ได้
3. เพิ่มฟอร์มเลือก/กรอกผู้รับการตรวจแทน `Demo Patient`
4. เพิ่ม export ผลเป็น PDF/CSV สำหรับใช้ประกอบการนำเสนอ
5. เพิ่มกราฟเปรียบเทียบค่าระหว่าง reference/target และแนวโน้มอุณหภูมิแบบ Real-time
6. เปลี่ยน dental map จาก JPG overlay เป็น SVG clickable map เพื่อความแม่นยำ
7. เพิ่มระบบ login แยกบทบาททันตแพทย์/ผู้ดูแล/ผู้สาธิต
8. เพิ่มชุดข้อความภาษาอังกฤษเพื่อใช้พรีเซนต์แบบ bilingual

## 19. สรุปสถานะปัจจุบัน

เว็บ PulseDent Platform ในโฟลเดอร์ `web_app` ตอนนี้รองรับ **การควบคุมการวัดแบบสองทิศทาง (Two-Way Toggle Start/Stop) และการรับค่าอุณหภูมิแบบ Real-time จากบอร์ด ESP32 ผ่าน Firebase Realtime Database** ร่วมกับระบบจำลองได้อย่างสมบูรณ์:
- แยกแสดงสถานะการเชื่อมต่อ (`Connection: Online / สัญญาณไม่อัปเดต / Offline`) และสถานะการวัด (`Measurement: Standby / Measuring / ไม่พร้อมวัด`) ตามอายุของ Heartbeat (`state/lastSeen`) และ `latest/timestamp` จริงใน Firebase (เกณฑ์ Stale 6 วินาที, Offline 12 วินาที)
- สั่ง **เริ่มการวัด / หยุดการวัด** ได้ทั้งจากปุ่มบนหน้าเว็บและปุ่มกดจริงบนบอร์ด ESP32 (GPIO 18) โดยซิงก์สถานะตรงกันแบบ Real-time และซ่อนค่าอุณหภูมิค้างเป็น `--.-- °C` เมื่ออยู่ในโหมด Standby หรือ Offline
- สามารถคลิกเลือกฟันซี่ใดก็ได้บนแผนผัง (ทั้งฟันอ้างอิงและฟันเป้าหมาย) เพื่อกดนำค่าจาก ESP32 ไปใส่ในซี่ฟันนั้น ล็อกค่าแล้วสลับโหมด หรือเปิดโหมดส่งค่าสดอัตโนมัติ (Real-time Auto-Assign) ขณะกำลังวัด
- คำนวณผลต่าง ประเมินความเสี่ยง บันทึกประวัติ และปรับตั้งค่า Firebase URL / Device ID ได้จากหน้าเว็บโดยตรง
